3. 정보의 전송과 보관

로그인 인증정보와 검색 요청은 HTTPS로 서버에 전송됩니다. 앱의 로그인 토큰과 조회 결과는 앱 메모리에서 사용되며, 현재 앱 소스에는 이를 파일이나 로컬 데이터베이스에 영구 저장하는 기능이 없습니다. 로그아웃하면 앱의 토큰과 조회 결과를 비웁니다.

앱을 삭제하거나 로그아웃해도 서버의 기존 업무 기록이나 접속 기록이 자동으로 삭제되지는 않습니다. 로그 조회 시 서버에는 조회 사실을 나타내는 감사 이벤트가 추가됩니다.

업무·조회 감사 로그에 정기 자동 삭제를 적용하지 않습니다. 아래 내용은 방침 시행일 현재의 보관 설정입니다.

구분보관 방식
업무·조회 감사 로그 운영 및 감사 목적으로 보관하며, 정해진 일수 경과에 따른 자동 삭제는 적용하지 않습니다. 삭제 요청은 운영자가 본인·권한과 처리 가능 범위를 확인한 뒤 개별 처리합니다.
일반 클라우드 로그 Cloud Logging의 _Default 버킷 보관기간은 30일입니다.
Google Cloud 필수 감사 로그 Cloud Logging의 _Required 버킷 보관기간은 400일이며 잠금 상태입니다. 이는 업무 기록을 저장하는 Firestore 감사 로그와 별개의 인프라 감사 로그입니다.
Firestore 복구·백업 현재 시점 복구(PITR) 및 예약 백업을 사용하지 않습니다.

보관 목적이 달성되어 더 이상 필요하지 않은 정보나 정당한 삭제 요청 대상 정보는 운영자가 관련 법령과 처리 권한을 확인하여 개별 삭제합니다. 전자적 기록은 해당 서버 저장소에서 삭제하며, 백업이나 별도 보관 의무가 있는 경우에는 처리 범위와 보관 사유를 요청자에게 안내합니다.

자동 삭제 기능이 없다는 이유로 삭제 요청을 할 수 없는 것은 아닙니다. Google Cloud 필수 감사 로그 등에는 별도의 서비스 보관 정책이 적용되므로 업무 감사 로그와 동일한 방식으로 즉시 삭제되지 않을 수 있습니다.

4. 외부 서비스와 처리 관계

앱은 Google 로그인을 사용하고, 서버는 Google Cloud의 Cloud Run 및 Firestore를 이용합니다. Google Play를 통한 설치와 업데이트에는 Google Play 서비스가 사용됩니다.

확인된 Firestore 데이터베이스 위치는 asia-northeast3(서울)입니다. Cloud Logging의 _Default 및 _Required 버킷 위치는 global로 표시됩니다. global 설정만으로 특정 저장 국가를 단정할 수 없으며, 모든 정보가 한국에만 저장된다고 안내하지 않습니다.

앱 소스에는 광고 SDK나 광고 식별자를 이용하는 기능이 포함되어 있지 않습니다. Google 서비스 자체의 데이터 처리에 대해서는 Google 개인정보처리방침도 확인할 수 있습니다.

Google 서비스는 로그인·접근 권한 확인, 서버 실행, 데이터 저장, 접속·오류 기록 처리 및 앱 배포를 위해 이용합니다. 로그인 또는 서비스 요청 시 필요한 정보가 네트워크를 통해 해당 서비스에 전달되며, 저장된 기록의 보관 방식은 제3항과 같습니다. global 로깅 및 Google 계정 서비스 처리에는 국외의 인프라가 이용될 수 있습니다. 자세한 처리 조건은 Google Cloud 데이터 처리 부속약관과 Google 개인정보처리방침을 확인할 수 있습니다.
